─── JUSTIFICATION TEXT (for coding) ───

[DOMAIN]
Value: CPS
Evidence: Abstract: "In this paper, we introduce RIoTPot, a modular and hybrid-interaction honeypot for Internet-of-Things (IoT) and Operational Technology (OT) protocols mainly used in Industrial Control System environments." Proposes, designs, and deploys a new honeypot as its primary contribution.

[INTERACTION LEVEL]
Evidence: Section 2: explicitly introduces a "hybrid-interaction" model enabling users to "switch between low- and high-interaction modes." Low-interaction via software packages; high-interaction via containers running full protocol implementations. Hybrid model spans both classified as medium overall.

[THREAT MODEL]
Value: Adversaries targeting IoT and OT protocols including Telnet, SSH, CoAP, Modbus, and MQTT. Both automated scanners and sophisticated attackers targeting ICS/SCADA environments.
Evidence: Section 3: "A total of 7,587 attacks were observed across all the protocols simulated by RIoTPot." Section 1: "low-interaction honeypots are prone to fingerprinting attacks due to their limited emulation capabilities."

[IRB / ETHICS COMMITTEE]
Evidence: No mention of IRB, ethics committee, or institutional approval.

[CONSENT MODEL]
Evidence: Section 3: "We define an attack as any interaction with the honeypot as there is no production value whatsoever." All interactions logged without notification. No consent model.

[DATA TYPES COLLECTED]
Evidence: Section 2: "The attack capture component is responsible for storing the attack packets as pcap files, using tcpdump." Section 3: "recurring sessions from same suspicious actors on the high-interaction mode, that included topic creation, subscription and deletion, and modification of existing messages."

[PROTOCOLS & PORTS]
Evidence: Section 3: "In the low-interaction variant, the protocols SSH, Telnet, HTTP, MQTT, CoAP and Modbus were simulated through the plug-in packages, while the high-interaction variant simulated the MQTT protocol in a container."

[DATA SENSITIVITY]
Value: Medium
Evidence: Attack traffic includes attacker IP addresses and detailed MQTT interaction records (topic creation, message modification). No personal user data collected; medium sensitivity given identifiable attacker network metadata and ICS protocol interaction logs.

[DATA MINIMIZATION]
Value: Not discussed
Evidence: No data minimization. Noise filter removes known scanning engines (Shodan, Censys) but full attacker IPs retained.

[DATA RETENTION POLICY]
Evidence: No retention policy mentioned.

[DATA SHARING]
Value: Source code publicly released (GitHub: aau-network-security/riotpot)
Evidence: Section 2: GitHub link provided. RIoTPot is fully open-source with documentation.

[JURISDICTION / LEGAL]
Evidence: No legal or jurisdiction analysis despite deploying internet-facing honeypots emulating ICS/OT protocols (Modbus, MQTT, CoAP) used in critical infrastructure.

[CONTAINMENT & HARM]
Evidence: Section 2: "The attack database stores all the attack traffic received on the honeypot. The database is setup as an independent module to ensure data availability even if a honeypot module is down." Containers provide process isolation for high-interaction MQTT service.

[DECEPTION FRAMING]
Evidence: Deception framed entirely technically. No ethical framing of emulating ICS/SCADA protocols (Modbus used in power plants, water treatment) as a deception mechanism.

[RESEARCHER RESPONSIBILITY]
Value: Not discussed
Evidence: No researcher responsibility discussion. No acknowledgement of dual-use risks of publishing open-source ICS/OT honeypot designs.

[ETHICAL GAPS]
Value: No IRB; no ethics section; open-source ICS/OT honeypot emulating Modbus (industrial control) creates dual-use risk attackers can use the code to test their tools against a realistic ICS honeypot before attacking real critical infrastructure.
Evidence: Open-source release of RIoTPot with Modbus, MQTT, and CoAP emulation creates dual-use concern: the same code enabling defenders to collect threat intelligence can help attackers test ICS attack tools against a realistic honeypot before targeting real power plants or water treatment facilities. This is not acknowledged in the paper.

[RELEVANCE TO PROJECT]
Evidence: Section 4: "as future work, we aim to extend RIoTPot to support more IoT and OT protocols like S7, DNP3, Fieldbus and Profibus." These are nuclear plant and industrial protocols. Open-source ICS honeypot design without ethical governance is precisely the gap HoneySat's framework addresses.

[DEPLOYMENT]
Value: Yes (deployed on public internet with public IPs for one week)
Evidence: Section 3: "The honeypot was deployed in both low and high interaction modes on two hosts in our lab. The hosts were assigned a public IP each, under an unfiltered network." Real internet-facing one-week deployment collecting 7,587 attacks.
